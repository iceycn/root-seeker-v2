# RootSeeker v1.3.6

v1.3.5 之后的补丁：修好 Kubernetes 证据采集在本机 kubeconfig（含客户端证书）和 metrics-server 缺失时的行为。

## 修复

- **支持 kubeconfig / 客户端证书**：不再只认 Bearer Token。会按 `ROOTSEEKER_K8S_*`、集群内 ServiceAccount、再 `ROOTSEEKER_K8S_KUBECONFIG` / `KUBECONFIG` / `~/.kube/config` 的顺序补齐连接信息。Docker Desktop 一类默认用客户端证书的集群可以直接读。
- **metrics-server 降级**：`metrics.k8s.io` 不可用时，若 kubelet `stats/summary` 已给出 CPU / 内存，结果仍为成功，并把「metrics API 不可用」写入 `warnings`，不再放进 `errors`，摘要也不会只写「水位正常」而把这件事藏掉。
- **两套「未开启」不再混用**：对外的 `k8s.status` 仍然只扫描外部 Kubernetes MCP；没有协议就跳过，不当作故障。真正读集群时，只有显式设置 `ROOTSEEKER_K8S_ENABLED=false` 才会关闭；未设置时，只要已有 kubeconfig 或 token / 证书就会尝试连接。
- 工作区根目录的 `tmp_*` 草稿文件不再容易被误提交。

MCP 扫描语义与 v1.3.5 相同：先扫协议，再读集群。

## 升级说明

```bash
git clone https://github.com/iceycn/root-seeker-v2.git
cd root-seeker-v2
git checkout v1.3.6
```

从既有 Compose 栈升级时，请重建会跑排查的服务（或拉取已发布的 `v1.3.6` / `latest` 镜像）。如果之前用 `--pull` 起的是旧镜像，API 里不会有这些修复，表现为 `k8s.*` 未注册或本机证书认证失败。

```powershell
docker compose build --pull=false api admin worker scheduler
docker compose up -d --force-recreate --no-deps api admin worker scheduler
```

若 API 跑在容器里、集群在宿主机（例如 Docker Desktop），需要把 kubeconfig 和证书挂进容器，并把 API Server 写成容器能访问的地址（常见为 `host.docker.internal`）。变量见 `.env.example`。

| 服务 | 地址 |
| --- | --- |
| 宣传首页 | http://localhost:8010/ |
| Admin 控制台 | http://localhost:8010/admin |
| API | http://localhost:8000 |
