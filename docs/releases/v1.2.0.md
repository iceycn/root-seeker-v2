# RootSeeker v1.2.0

v1.1.4 之后的功能版本：Admin 控制台增加 **登录、首次引导与用户管理**，保护 `/api/*` 与 SPA 页面访问。

## 亮点

- **首次打开引导（bootstrap）**：当 `users` 表为空时，仅可调用 `POST /api/auth/bootstrap` 创建首个管理员；完成后进入正常登录流程
- **Cookie 会话登录**：`POST /api/auth/login` 校验用户名与 bcrypt 哈希密码，下发 HttpOnly Cookie `rootseeker_admin_session`；未认证访问 `/api/*` 返回 401，访问页面路由 302 至 `/login`
- **用户管理**：已登录用户可列表/创建用户、修改自己的密码、删除用户（含删除自己）；删除至无用户时回到 bootstrap
- **密码安全**：仅存 bcrypt 哈希，接口与列表不返回明文或哈希字段

## 本版本主要变更

### Admin 认证与用户

- 内存会话（进程重启后需重新登录；会话 TTL 约 12 小时）
- `users` 表：MySQL / SQLite / 内存后端；Admin 连接持久化后端时使用 `CREATE TABLE IF NOT EXISTS` 建表。全新 MySQL 栈会执行 `mysql/init/01_schema.sql`，但**沿用已有 MySQL 数据卷升级时不会重跑 init**——依赖 Admin 运行时建表，无需手工迁移脚本
- 前端：`/login`、`/users` 页面；顶栏当前用户与退出

### 文档

- 业务逻辑文档补充 Admin 认证与用户 API
- 设计规格状态同步为已实现

## 升级说明

```bash
git clone https://github.com/iceycn/root-seeker-v2.git
cd root-seeker-v2
git checkout v1.2.0
```

从既有 Compose 栈升级时，建议重建 Admin（含前端）：

```powershell
docker compose build --pull=false admin
docker compose up -d --force-recreate --no-deps admin
```

**注意**

- 升级后首次打开 Admin：若尚无用户，请在 `/login` 完成 bootstrap 创建首个账号
- Admin 进程重启后内存会话清空，需重新登录
- 使用持久化 MySQL 且**保留旧数据卷**时：容器升级**不会**再次执行 `mysql/init`；`users` 表由 Admin 启动连接 MySQL 时的 `CREATE TABLE IF NOT EXISTS` 创建（与 SQLite 后端行为一致）

| 服务 | 地址 |
| --- | --- |
| API | http://localhost:8000 |
| Admin | http://localhost:8010/admin |
