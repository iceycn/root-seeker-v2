# RootSeeker v1.1.0

面向公司内网的 **AI 驱动故障排查与根因发现平台** 第二个正式版本。

相对 v1.0.0，本版本把默认排查从 YAML Flow 步进器全面切换为 **Agent Playbook（AttemptRunner）**，并显著增强错误日志归约、图谱仓库匹配与出站通知可读性。

> 本地全栈（Admin `:8010` / API `:8000`）已用真实 SLS / knowledge-api 堆栈验证主链路。欢迎通过 [Issue](https://github.com/iceycn/root-seeker-v2/issues) 反馈。

## 亮点

- **Agent 默认执行器**：`AttemptRunner` 成为唯一默认排查路径；去掉 YAML Flow 步进器与 step resume
- **标准 Skill 包**：三根注册表（builtin / custom / external）+ `SKILL.md` 解析，支持目录 / zip / git 安装与 overlay
- **外部 MCP stdio**：Skill 可声明并使用外部 MCP 工具；高级设置支持环境变量注入
- **日志与根因可读性**：SLS 嵌套 JSON unwrap、SOFA 服务名推断、JDK 帧过滤；根因标题优先异常摘要
- **规则即时问题摘要**：通知与错误排查页展示「服务 + 故障方法 + 异常」一句话总结（不依赖 AI）

## 本版本主要变更

### Skill / Agent Runtime

- 标准 `SKILL.md` 解析，取消 sidecar 依赖
- `PlaybookResolver`、`SkillEnvResolver`（优先级与密钥处理）
- Admin Skill overlay 持久化与安装 API（含 GitHub `owner/repo`）
- Playbook 允许的 WRITE 工具（如报告后自动 `notify.send`）不再被规划器误剥；规划阶段不再要求 Agent 主动选 notify

### 排查与根因质量

- `unwrap_embedded_log_text`：剥开 SLS / 告警 JSON 壳，支持 `stackTrace` 与截断 JSON salvage
- 根因 title/narrative 去「共分析 N 条…」过程话术，优先 `exception_summary`
- GitNexus 仓库别名改为 exact / 后缀 / path-token，避免 `order-service` 误匹配 `border-service`
- `build_problem_summary`：规则即时问题摘要写入报告与通知「问题：…」行

### Admin / 文档

- Playbook UI 可正常服务；README 增加 v1.1.0 界面截图
- 错误排查结果卡新增「问题摘要」

### 测试与稳定性

- Worker / SQLite `CASE_RUN`、CLI demo 在无 YAML Flow 时以 stub planner 跑通
- Agent 失败状态可正确上浮；overlay role 可用

## 升级说明

```bash
git clone https://github.com/iceycn/root-seeker-v2.git
cd root-seeker-v2
git checkout v1.1.0
cp .env.docker .env
```

**Windows**

```powershell
.\setup.ps1      # 国际源
.\setup-cn.ps1   # 国内加速
```

**macOS / Linux**

```bash
chmod +x setup.sh setup-cn.sh
./setup.sh       # 国际源
./setup-cn.sh    # 国内加速
```

从 v1.0.0 升级 Compose 栈时，建议重建 Admin（含前端）：

```powershell
docker compose build --pull=false admin
docker compose up -d --force-recreate --no-deps admin
```

启动后：

| 服务 | 地址 |
| --- | --- |
| API | http://localhost:8000 （OpenAPI：`/docs`） |
| Admin | http://localhost:8010/admin |
| 错误排查 | http://localhost:8010/error-chat |

## 破坏性 / 行为变化

- 默认排查不再走 YAML Flow 步进器；自定义若依赖旧 sidecar / step resume，需改为标准 Skill Playbook
- 通知在报告生成后由运行时自动发送；playbook 正文不再要求规划 `notify.send`
- 根因与通知文案更偏「问题是什么」，不再堆砌证据计数过程话术

## 已知限制

- 问题摘要为规则拼接，不等同于 AI 人话根因；深度解释仍看异步 AI 分析
- GitHub 网页域名在部分网络下不稳定时，可用 Gitee 镜像同步：`https://gitee.com/icey_1/root-seeker-v2`
- Kubernetes 生产级加固（SLO 看板等）仍在规划中
