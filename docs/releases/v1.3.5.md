# RootSeeker v1.3.5

v1.3.2 之后的功能版本：默认排查在日志查询之后，可以补充 **Kubernetes 运行时证据**（CPU、内存、磁盘，以及最近一段时间的容器日志）。

## 亮点

- **先扫协议，再读集群**：`k8s.status` 只检查已经注册的外部 MCP。server id、工具名或标签里出现 `k8s`、`kubernetes`、`kubectl` 才算命中
- **没有协议就跳过**：`mcp_present=false` 时不访问集群，也不把这一步当成故障（不使用 `status=disabled`）
- **一次快照**：`k8s.collect_snapshot` 同时返回 CPU、内存、磁盘和日志窗口；需要核对时再调用单项工具
- **日志窗口默认 5 分钟**：`ROOTSEEKER_K8S_LOG_WINDOW_MINUTES`，单次可用 `since_minutes` 覆盖

## 本版本主要变更

### MCP

- `k8s.status`
- `k8s.read_cpu`
- `k8s.read_memory`
- `k8s.read_disk`
- `k8s.read_logs`
- `k8s.collect_snapshot`

内置的 `k8s.*` 工具本身不算 Kubernetes 协议。使用率达到 85% 及以上会写入 `anomalies`。

### Skill

- helper：`skills/builtin/k8s-status`、`skills/builtin/k8s-runtime`
- playbook `default-log-triage` 在日志查询之后调用上述工具

### 配置

集群读取还需要 `ROOTSEEKER_K8S_ENABLED=true`，以及 API 地址和 token。留空时，若进程在集群内，会使用 ServiceAccount 挂载。变量见 `.env.example` / `.env.docker`，Compose 会把它们传给 api、admin、worker、scheduler。

## 升级说明

```bash
git clone https://github.com/iceycn/root-seeker-v2.git
cd root-seeker-v2
git checkout v1.3.5
```

从既有 Compose 栈升级时，重建会跑排查的服务：

```powershell
docker compose build --pull=false api admin worker scheduler
docker compose up -d --force-recreate --no-deps api admin worker scheduler
```

未配置外部 Kubernetes MCP 时，排查行为与 v1.3.2 相同：这一步被跳过。

| 服务 | 地址 |
| --- | --- |
| 宣传首页 | http://localhost:8010/ |
| Admin 控制台 | http://localhost:8010/admin |
| API | http://localhost:8000 |
